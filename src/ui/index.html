Install Android to the virtual disk

The VM window is open. Follow these six steps once; afterwards ApkStart boots from the disk and needs no image.

  1. Boot menu: pick Installation - Install Android-x86 to harddisk with ↓ and press Enter
  2. Choose Partition: select Create/Modify partitions; answer No to GPT
  3. cfdisk: New → Primary → accept the size → Bootable → Write → type yes → Quit
  4. Format: choose vda1 → pick ext4 → Yes
  5. Bootloader: Install GRUB → Yes; Install /system as read-write → Yes
  6. Done: at 100% click “I finished the installation” below (ApkStart reboots and takes over)

If adb is reported as disconnected: press Ctrl+Alt+F1 in the VM window and run setprop service.adb.tcp.port 5555、stop adbd、start adbd， then Ctrl+Alt+F7 to return to the graphical session.

Automatic mode (default, nothing to configure)
Detecting…
Memory, cores, render backend, port and acceleration are all chosen automatically; failed starts step down and retry.
Measuring…
One shared system image, app data in a delta layer; old images, snapshots, logs and lock files are reclaimable. Logs rotate at the cap. "Reset Android data" really deletes gigabytes of user data, keeping only the system.
The report helps debugging; rebuilding restores desktop and menu entries
Stays in the tray after login; desktop icons open apps instantly.
App window
Toggle with F11 or the tray menu; fullscreen only enlarges the window, switching does not restart the app.
In window mode you can drag the border to any size; this sets the Android render size — smaller is cheaper.
Mouse buttons
The emulator maps the left button to a finger tap natively; drag to swipe.
By default the emulator treats right-click as another tap. When enabled, right-click only goes back.
Smooth mode merges a short burst of scrolling into one swipe gesture, avoiding judder and an adb process per notch.
Side-button mapping needs a global mouse hook, installed only while the app window is focused and removed on blur.
These mappings apply only while the app window is focused; afterwards the mouse behaves normally.
Performance and resources
Controls how much CPU the VM gets and how sharp the picture is. Video apps stutter → Smooth; small apps on the side → Frugal. Applies on the next launch.
Growing happens in place: apps and saves are kept; the next launch takes a few extra seconds.
Reading the data partition…
Point Android at public DNS servers. By default Android forwards to the host DNS, which can take hundreds of ms on VPN or corporate networks. Turn off if intranet names misbehave.
Plays app sounds and video audio. Turn off only if you need no sound and want to save CPU.
The second launch takes seconds, at the cost of a ~2-3 GB ram.bin. Turn off on tight disks: it only affects start time.
Container details (advanced)
Caps vCPU quota and lowers priority so the desktop keeps its CPU. The resource policy above sets this automatically.
Game mode keeps a higher CPU priority and reduces host polling for the lowest input and frame latency; other programs slow down. With no app window the container parks at low priority.
Also disables Play Store, setup wizard and printing background packages. If an app complains about missing Google Play services, turning this off restores them.
Boots Android in the background after start-up (fully hidden). Opening an app then takes a moment instead of 20+ seconds. Idle cost is about 1 GB of RAM; without it the first open is a cold boot.
Android boots once and stays resident; opening an app starts it and stops the others. Closing the last window clears the background and parks the container.
Downloads and update sources
Auto asks GitHub and Gitee for the latest version, probes every URL with 256 KB and downloads from the fastest; one broken source does not block updates.
When direct GitHub is slow, also probe the ghfast.top / gh-proxy.com relays (public release files only, no accounts). Off means direct + your own prefix.
When set, only your prefix is used and the public mirrors are skipped. Empty lets the auto logic decide. It is prepended to real URLs.
Large files download in parallel chunks. Eight threads saturate most home links; try 16 on a stable network.
Gitee update source (optional)
This repository is public and Gitee release lists are readable anonymously, so empty works. Fill it only when Gitee rate limits you (403/429) or you read a private branch: gitee.com → Settings → Private tokens, tick only "projects"; it is used to list releases and uploads nothing.

System integration
Double-clicking an APK installs it into ApkStart (current user only, no root)
This is the biggest consumer (gigabytes). Moving it to another volume relieves the system disk; restart afterwards, existing data is not moved automatically.
This is what really eats disk: the data partition (6 GB by default, growable above) plus the quickboot snapshot (~2-3 GB). On a tight disk point it elsewhere and restart; the old apkstart.avd can be moved over and deleted.
Uninstalling drops the .apk association and removes the program; portable builds delete the directory manually.
